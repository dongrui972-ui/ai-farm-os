# AI Farm OS 专家委员会与质量门禁

本项目采用多专业联合评审。任何“可执行建议”都必须同时通过农业合理性、设备安全、数据可信、软件质量和角色权限检查，不能只凭单一模型结论直接下发。

这些“专家”是系统设计与评审职责，不代表程序已经取得个人执业资格，也不替代属地农技、植保、农机安全或监管人员签字。当前版本的农业数值、设备状态、履历、图片和模型指标均为仿真数据；生产启用前必须换成有来源、时间、质量码和责任人的本场数据。

## 专家角色

| 专家 | 主要职责 | 必须阻断的情况 |
|---|---|---|
| 农艺与作物专家 | 生育期、农时、水肥、病虫草害、采收阈值 | 作物/生育期不匹配；关键观测缺失；处方超出适用范围 |
| 农机与作业安全专家 | 机具匹配、道路冲突、作业窗口、维护和安全联锁 | 人机混行风险；机具能力不足；天气或地况不满足 |
| 灌溉与土壤专家 | 墒情、盐分、流量、轮灌和养分处方 | 单位/深度未知；水量超限；阀泵状态不可确认 |
| 产品与运营专家 | 首页决策优先级、责任人、截止时间、闭环 | 建议没有下一步动作、负责人、时限或回执 |
| 数据治理专家 | 来源、新鲜度、质量码、主键、版本与证据链 | 模拟数据冒充实时数据；来源/单位/时间缺失 |
| 软件架构专家 | 前后端契约、状态一致性、降级策略、可维护性 | 后端与本地引擎静默混用并产生状态分叉 |
| 测试与可靠性专家 | 单元、API、浏览器、响应式、回归与故障注入 | 关键流程无自动验证；异常路径不可复现 |
| 安全与权限专家 | 输入校验、最小权限、角色门禁、安全响应头 | 监管角色可执行生产指令；危险动作无确认或审计 |
| 无障碍与户外可读性专家 | 键盘、ARIA、对比度、触控目标、小屏适配 | 关键动作仅鼠标可用；状态只靠颜色表达 |

## 国际规范映射

- FAO 数字农业与 AI 创新框架：落实数据治理、问责、农户数据权利、沙箱验证和人工监督。
- USDA NRCS Irrigation Water Management 449：灌溉建议核验时机、用量、速率、根层/土壤、有效降雨、效率和本地技术依据。
- ISO 25119：把农机安全相关控制链与业务展示分离，故障和未知状态默认拒绝执行。
- ISO 11783：以 ISOBUS/任务控制器互操作为目标能力；未经过设备身份、兼容性、任务交换和 ACK 验收时，不标“已接入”。

规范入口与版本说明见 `docs/FINAL_SPEC.md` 第 4 节；项目不复制标准全文，实施时应由具备授权的团队核对正式版本。

## 联合决策流程

1. 数据治理专家先确认来源、采集时间、单位和质量码。
2. 农艺/土壤专家生成候选建议，并列出适用条件与证据缺口。
3. 农机专家校验机具、人员、天气窗、道路和安全联锁。
4. 软件与安全专家检查角色权限、幂等、失败回滚和审计留痕。
5. 产品专家把结论转换为“动作、原因、风险、责任人、截止时间、回执”。
6. 测试专家执行自动回归；高风险动作必须保留人工门禁。

## 发布门禁

- `P0`：数据泄露、越权执行、危险机具/水肥指令、主流程不可用。必须清零。
- `P1`：数据口径错误、状态分叉、关键页面无反馈、移动端不可操作。必须有修复与回归测试。
- `P2`：视觉一致性、辅助说明、低频功能。纳入校准清单，不得破坏 P0/P1。
- 所有实时/在线/AI 指标都必须明确标注为“真实接入、后端仿真或本地仿真”之一。
- 每轮交付至少执行：Python/JavaScript 静态检查、API 冒烟、三角色权限回归、桌面与窄屏浏览器检查、控制台错误检查。
